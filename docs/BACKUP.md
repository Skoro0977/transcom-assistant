# Резервная копия и восстановление

Сначала остановите сервер Ctrl+C и отдельные процессы worker. Скрипт откажется создавать копию, пока порт 8000 занят. Используется штатный SQLite backup под блокировкой записей.

Копия включает базу, управляемые оригиналы всех редакций, исходный архив, входящие папки, .env, файл учетных записей и ключи зашифрованных подключений. Производные зависимости, OCR кэш и временные файлы устанавливаются заново. ZIP содержит секреты: он остается в закрытой data/local/backups на D с доступом текущего пользователя и SYSTEM. Не загружайте его в GitHub и не передавайте как архив исходного кода.

Создание:

```powershell
. 'D:\CodexData\Projects\transcom-assistant\scripts\dev-env.ps1'
& '.venv\Scripts\python.exe' -B -m scripts.backup create
```

Проверенное восстановление последней копии в новую папку:

```powershell
. 'D:\CodexData\Projects\transcom-assistant\scripts\dev-env.ps1'
$backupEntry = Get-ChildItem -LiteralPath 'D:\CodexData\Projects\transcom-assistant\data\local\backups' -Filter '*.zip' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$backupDigest = (Get-Content -LiteralPath ([System.IO.Path]::ChangeExtension($backupEntry.FullName, '.sha256')) -Raw).Trim()
$restoreDirectory = Join-Path 'D:\CodexData\Temp' ('transcom-restored-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
& '.venv\Scripts\python.exe' -B -m scripts.backup restore $backupEntry.FullName --destination $restoreDirectory --sha256 $backupDigest
```

При создании проверяются целостность SQLite, внешние ключи, SHA256 оригиналов и размер манифеста. При восстановлении дополнительно проверяются SHA256 архива и каждого файла, допустимые пути, число и объем записей. Общие пределы создания и восстановления: 50 000 файлов, 8 МиБ для манифеста, 20 ГиБ для всех распакованных данных вместе с манифестом. Существующая папка никогда не перезаписывается. При ошибке остается отдельная папка для разбора, рабочие данные не заменяются.

В восстановленной базе сессии и одноразовые коды аннулированы, источники и мессенджеры выключены, входящие пути перенесены в новую папку. В .env worker и массовый облачный индекс выключены, DATABASE_URL указывает на новую базу. Это позволяет проверить копию без отправки данных и повторного приема событий.

Для запуска восстановленного экземпляра распакуйте отдельный ZIP исходного кода из data/local/releases в эту же новую папку после восстановления данных. В ZIP кода нет data/.env. Выполните scripts/setup.ps1 из новой папки, затем scripts/start.ps1 при остановленном исходном сервере. Скрипты определяют корень по своему местоположению и требуют D. Учетные данные берите из восстановленного data/local/accounts.csv. Только после проверки настроек вручную включайте нужные источники и WORKER_ENABLED.

Окончательное удаление документа в приложении не стирает уже созданные резервные копии или исходные папки. Копии очищаются отдельно по решению владельца. Новые программы и папки на C этот процесс не создает.
