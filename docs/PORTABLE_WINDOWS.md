# Запуск на Windows без диска D

## Ветка и доступ

Ветка: [feat/portable-windows](https://github.com/Skoro0977/transcom-assistant/tree/feat/portable-windows). У `kozlovskkiy` фактически проверено право Write. Авторизация GitHub нужна для клонирования закрытого репозитория и отправки коммитов. Пароль учетной записи GitHub вместо токена в Git вводить не требуется: используйте обычный вход через Git Credential Manager.

Инструкция установки и запуска с конкретными командами находится в README этой ветки. Скрипты поддерживают Windows PowerShell 5.1 и используют `-Portable` на компьютере без D. Python 3.11 должен быть установлен заранее; setup выбирает `py -3.11`, а при отсутствии launcher проверяет `python.exe`. Node скачивается внутрь `data/local/runtime`, архив проверяется по официальному закрепленному SHA256. Системный Node и профиль не меняются.

## Где находятся файлы

Все пути относятся к папке клона, например `C:/Projects/transcom-assistant-portable`:

| Содержимое | Путь относительно клона |
| --- | --- |
| Python и зависимости | .venv |
| Node | data/local/runtime/node-v26.13.1-win-x64 |
| Архив Node | data/local/downloads |
| Кэши Python/npm и временные файлы | data/local/dev |
| База и оригиналы | data/transcom.db, data/blobs |
| Временные файлы обработки документов | data/tmp |
| Индивидуальные пароли | data/local/accounts.csv |
| Ключ GigaChat | .env |

Режим разрешает локальный диск самого проекта. SQLite URI, относительный путь базы, сетевой путь проекта, выход из входящей папки и перенаправления резервной копии через ссылки по-прежнему запрещены. На машине владельца режим без `-Portable` сохраняет требование D. Для прямых Python-команд сначала подключайте dev-env.ps1 с тем же параметром.

Резервная копия после остановки сервера:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. .\scripts\dev-env.ps1 -Portable
& .\.venv\Scripts\python.exe -B -m scripts.backup create
```

Копия содержит секреты, хранить ее закрыто. Восстановление разрешено только в новую папку на диске этой копии проекта, с проверкой SHA256 по BACKUP.md.

## Задача T25 для Ярослава

Исполнитель: `kozlovskkiy`, [GitHub-задача №1](https://github.com/Skoro0977/transcom-assistant/issues/1). Статус: зарезервирована за Ярославом, исправление в этой ветке не выполнялось.

Независимо подтвержденный пример на искусственных данных:

1. Текущая редакция документа v3 содержит текст: "Требование: выполнить гидравлический расчет и проверить расход газа. Ответственный: Иван Тестовый. Срок: 05.12.2026."
2. Действующая подтвержденная карточка "Выполнить гидравлический расчет и проверить расход газа", Revision 2, имеет due_date=2026-12-07.
3. Векторы отсутствуют, текущий поиск по словам. Вопрос "Какой текущий срок поручения в искусственном примере?" получает один документ v3. Карточка не попадает в контекст, GigaChat отвечает 05.12.2026.
4. Точный вопрос с названием карточки получает подтвержденный срок 07.12.2026.

Исправление должно дать общему вопросу актуальную подтвержденную карточку и отличать ее от текста документа, сохраняя права проекта, текущие/исторические редакции, архив и purge. Нужна регрессия на искусственных данных без реального ключа и без обращения к провайдеру. Основные места: apps/api/search.py, apps/api/assistant.py, tests/test_auth.py. В тестах уже есть fixture isolated и безопасные подмены GigaChat.

Реальная база с демонстрационным проектом не передается. Восстановите минимальный искусственный сценарий в тестовой fixture либо в своей локальной копии через обычные подтверждения интерфейса. Не загружайте рабочий архив владельца и .env в Git.

## Проверка переносимости

Windows job в GitHub Actions распаковывает только Git-код в новую папку `C:/Transcom CI/project`, устанавливает окружение через Windows PowerShell 5.1, выполняет миграции и критичные тесты. Затем штатный start.ps1 запускает приложение на localhost:8002; проверяются frontend, health, вход и выход с точным браузерным Origin. Папка содержит пробел, чтобы проверить кавычки в командах. Этот запуск на C выполняется в отдельном GitHub runner; на компьютере владельца новые файлы остаются на D.

Итог фактических прогонов фиксируется в WORK_LOG.md и независимом ревью T26. Облачная проверка не подтверждает наличие Python, сетевого доступа и индивидуальных ключей на компьютере Ярослава.
