## Работа с данными

Исходный архив уже импортирован в "Газопровод Ренево". Повторно загружать его целиком не требуется. Сначала разберите документы со статусом подготовки, затем анализируйте нужные источники и проверяйте предложения. Сводка использует подтвержденные карточки и отдельно показывает новые предложения и поступления.

Изменения через чат проходят подготовку и отдельное решение. При одновременном изменении карточки устаревшее предложение потребует повторной подготовки. Новая редакция документа сохраняет прежнюю. Архив скрывает документ из текущей работы; окончательное удаление требует отдельной последовательности подтверждений. Старые резервные копии и исходные папки очищаются отдельно владельцем.

Папка приема, Gmail и Яндекс настраиваются в "Источники данных". Мессенджеры и входящий API настраиваются там же. Подробности: SOURCES.md и INTEGRATIONS.md. Для бот-команд каждый отправитель связывает свой ID с веб-аккаунтом одноразовым кодом. Включенные ответы бота доступны всем участникам разрешенного чата, поэтому задавайте конкретный чат проекта.

## Совместная разработка

Принятый код в main и последовательные коммиты задач загружены в закрытый репозиторий [Skoro0977/transcom-assistant](https://github.com/Skoro0977/transcom-assistant). Не редактируйте одну общую рабочую папку одновременно. Каждый разработчик получает отдельный клон на D, работает в короткой ветке и создает PR в main. Проверка и ревью предшествуют объединению. GitHub Actions при push и PR проверяет зависимости, Ruff, сборку frontend, OCR, миграции и тесты. Результаты доступны во вкладке Actions.

Репозиторий создан 15.11.2026 под владельцем Skoro0977, приватность проверена через API. Локальный origin настроен, main отслеживает origin/main. Перед отправкой независимо проверена история, после отправки проверено удаленное дерево: .env, data, архив заказчика и учетные записи отсутствуют. Коллега приглашается с Write после предоставления его логина. GitLab по ответам не требуется.

На втором компьютере код размещается на D. Нужны Python 3.11 и переносимая Node 26.13.1 в документированном каталоге D. Затем выполняются scripts/setup.ps1 и настройка собственной .env. Для переноса существующего пилота используйте закрытую копию по BACKUP.md. ZIP исходников и ZIP данных имеют разное содержимое: ZIP данных содержит ключи и пароли и должен оставаться закрытым.

## Следующие действия после предоставления доступов

1. После получения логина коллеги пригласить его в закрытый GitHub с ролью Write, проверить его доступ и первый PR. Состояние проверок main смотреть во вкладке Actions.
2. Получить прямое разрешение на передачу текстов всего архива в GigaChat. Затем включить массовую индексацию, проверить очередь, размерность и полноту индекса. Без разрешения оставить локальный поиск.
3. Подключить конкретную почтовую папку и проверить одно настоящее письмо с вложением без изменения флагов и отправки.
4. После получения сервера и домена подготовить HTTPS, секреты окружения, резервирование, COOKIE_SECURE и ALLOWED_ORIGINS. Проверить сервер отдельно до подключения реального трафика.
5. Подключить тестовые Telegram/ВК чаты с указанными ID, проверить прием, новую редакцию, вопрос и отдельное подтверждение изменения. Включить ответы только для согласованного чата.
6. Пройти интерфейс под своей учетной записью и сверить инженерные результаты на выбранных реальных документах с руководителем проекта.
