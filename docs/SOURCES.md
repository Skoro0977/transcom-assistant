# Источники данных

В разделе "Источники данных" видна входящая папка каждого проекта на D. Добавьте источник типа "Папка" и поместите туда новые документы. Допускаются подпапки внутри этого же проекта. Чужие каталоги, другие проекты и диск C через интерфейс не подключаются. Готовый исходный архив уже импортирован отдельно; копировать его во входящую папку не требуется.

Проверка выполняется автоматически во время работы приложения. Файлы моложе трех секунд пропускаются до следующего прохода. За один проход принимаются пять изменившихся файлов, затем обработка продолжается. Обычный проход сверяет размер и время изменения, кнопка "Проверить сейчас" также пересчитывает содержимое. Неизмененные байты не создают новые редакции. A -> B -> A сохраняет три редакции. Удаление файла из входящей папки не удаляет управляемый оригинал. Архивный документ сам не возвращается в работу. Окончательно удаленные байты повторно не импортируются.

Для почты создайте отдельный источник Gmail или Яндекс и укажите папку с перепиской конкретного объекта. Подключение только читает IMAP через TLS на порту993: EXAMINE и BODY.PEEK, без изменения флагов, удаления и отправки писем. Письмо сохраняется неизменяемым EML, затем проходит тот же разбор, включая вложения. Учитываются UIDVALIDITY и UID; курсор и поступление фиксируются атомарно. При частичном сбое уже принятые письма не теряются. Письма больше100МиБ явно пропускаются с сообщением о подготовке. Первое подключение читает существующие письма выбранной папки, дальнейшие проходы новые UID.

Яндекс: включите IMAP и создайте пароль приложения согласно [официальной инструкции](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others). Сервер фиксирован imap.yandex.ru, SSL993.

Gmail: поддерживаются пароль приложения, если он доступен для аккаунта, и OAuth с Client ID, Client Secret и Refresh Token. Обычный пароль Google не подходит. Доступность пароля приложения зависит от двухэтапной проверки и политики аккаунта: [справка Google](https://support.google.com/accounts/answer/185833?hl=ru). Для OAuth получите согласие владельца и refresh token со scope https://mail.google.com/ в своем Google Cloud приложении. Код обновляет access token через официальный endpoint и использует XOAUTH2: [протокол Google](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol), [обновление токена](https://developers.google.com/identity/protocols/oauth2/web-server#offline). Браузерный мастер регистрации OAuth приложения в этой версии не реализован; реквизиты вводятся в настройках источника.

Секреты шифруются Fernet и сохраняются в data/local/source-secrets на D, вне Git и БД. Ключ шифрования хранится рядом в защищенной папке данных. Это защищает от случайного раскрытия БД, но не заменяет системные права доступа. Для переноса подключения нужно перенести весь каталог секретов с ключом или ввести реквизиты заново. API возвращает только признак наличия учетных данных. Пустые поля сохраняют текущие реквизиты того же аккаунта, заполненные поля обновляются. Для другого аккаунта требуется полный набор.

При потере владельцем доступа к проекту автоматическое чтение выключается. Участник с правом редактирования может заново сохранить источник от своего имени. Изменение настройки во время чтения отменяет публикацию старого результата. Ошибки показываются без паролей и ответов авторизации.

Реальные почтовые аккаунты пока не подключены: реквизиты не предоставлены. Протокол, курсоры, права, шифрование и повторная обработка проверены искусственным IMAP без отправки данных наружу.
