# Контракт данных и интерфейса

## Принципы

Все проектные ресурсы проверяются через членство пользователя. Результат модели и сообщение не изменяют базу напрямую: только сохраненное предложение и решение проверяющего. Номер редакции обязателен для изменения существующего состояния. Оригиналы неизменяемы, архив и активная выборка различаются.

## Состояния

- Обработка документа: queued, parsing, ready, needs_preparation, failed.
- Проверка предложения: pending, accepted, rejected. Отмена принятого решения создает следующую редакцию.
- Рабочий статус этапа: no_data, received, correction, customer_review, approved. Параллельные этапы и возвращение допустимы.
- Документ: active, archived, purged. Purged является окончательным удалением содержимого с предупреждением и повторным подтверждением.
- Риск имеет отдельные category, priority и status. Цвет не является состоянием проверки.

## Сущности и отношения

User связан с Project через Membership. Проект содержит Document, а Document содержит неизменяемые DocumentVersion. К редакции привязаны Chunk с точным локатором и Occurrence для каждого поступления. AttachmentLink связывает родительскую редакцию письма с редакцией вложения.

Предметные карточки хранятся в общей Record с явным kind: requirement, stage, task, event, risk или policy. Неизменяемая Revision хранит проверенные по схеме data, основания, автора и причину. Proposal относится к проекту, целевой карточке и базовой редакции; принятие создает Revision и Audit одной транзакцией. Метаданные документа меняются через Proposal вида document с отдельной проверкой версии Document, без создания фиктивной предметной карточки. ChatTurn сохраняет личную историю чата и использованные источники. Job хранит состояние обработки.

Source и SourceFile обеспечивают прием папки или почты и курсор. Integration, IntegrationMessage и Receipt (таблица integration_receipts) обеспечивают входящий API и мессенджеры; Receipt хранит состояние доставки ответа. BotActor связывает отправителя с веб-пользователем, BotTicket задает одноразовое подтверждение. Секреты подключений находятся в отдельном зашифрованном локальном хранилище. Notification относится к проекту и пользователю. Схема создания таблиц закреплена миграциями Alembic.

У источника различаются время документа, получения и подтверждения. Для событий видны эти даты, неизвестные значения не выдумываются. У цитаты есть version_id и locator, при переиндексации исходник остается доступным. Даты календарных сроков хранятся как даты; системное время как UTC с часовым поясом, показ в Europe/Moscow.

## API

| Область | Операции |
| --- | --- |
| /api/auth/login, /me, /logout | Вход, сессия и CSRF, выход. Регистрации нет |
| /api/projects | Список доступных объектов, создание |
| /api/projects/{id}/overview | Обзор, участники и состояния обработки документов |
| /api/projects/{id}/documents | Список, загрузка и редакции |
| /api/documents/{id}, /content | Редакции и основания в карточке; авторизованное чтение по номеру |
| /api/document-versions/{id}/content | Авторизованный оригинал точной редакции |
| /api/projects/{id}/proposals | Очередь проверки, фильтры |
| /api/proposals/{id}/decision | Решение с expected_version; повторное принятие и устаревшая версия запрещены |
| /api/projects/{id}/decisions | Выбранный набор без противоречий; ID и expected_version для каждого элемента |
| /api/projects/{id}/requirements, /records?kind=, /timeline | Принятые предметные данные и события, редактирование через предложения |
| /api/projects/{id}/stage-template | Семь предложений названий этапов, без автоматического принятия |
| /api/projects/{id}/search, /chat, /summary, /report | Поиск, вопросы, сводка и DOCX |
| /api/projects/{id}/chat/changes | Подготовка изменения выбранной карточки без принятия |
| /api/records/{id}/history | История принятой карточки и ее основания |
| /api/projects/{id}/sources | Контроль папки и почты |
| /api/projects/{id}/integrations | Настройка входящего API и мессенджеров |
| /api/incoming/{id}/files, /telegram, /vk | Прием с отдельной проверкой ключа и настроек подключения |
| /api/documents/{id}/archive, /purge-challenge, /purge | Исключение, предупреждение и окончательное подтверждение |

Путь {id} в таблице является обозначением параметра маршрута HTTP, а не пропущенным реквизитом сервера. Реальные учетные данные, URL почты и токены ботов не задаются вымышленными значениями.

Сервер возвращает 401 при отсутствии сессии, 403 при нехватке права, 404 для недоступного проектного ресурса, 409 при конфликте версии и 422 при некорректном вводе. Долгая операция возвращает ID задания. Интерфейс показывает обработку, частичный успех, источник, ошибку, конфликт и недостаток оснований.

## Первый сценарий

Вход -> проект -> загрузка -> статус обработки -> фрагмент основания -> предложение -> подтверждение/отклонение -> принятая карточка -> история. Все пользователи пилота имеют одинаковые рабочие возможности; роль admin/user и отдельные права сохраняются для будущей настройки.
