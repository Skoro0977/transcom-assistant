# Telegram, ВК и входящий API

В разделе Источники создается отдельное подключение проекта. Входящий ключ показывается один раз. В БД только хэш, токены ботов зашифрованы Fernet в data/local/source-secrets. Повторно токены не выводятся. Для ротации выключите старое подключение, создайте новое с другим названием и обновите адрес/ключ на стороне отправителя.

API принимает POST на адрес, показанный в карточке, Authorization Bearer с выданным ключом, multipart поля file и external_id. До100МиБ, разрешенные форматы. Та же пара ключа события и байтов безопасна; измененные байты с тем же external_id дают409. Для нового события нужен новый ID.

Telegram: настройте webhook на показанный HTTPS адрес, secret_token равен выданному входящему ключу. ВК Callback API: тот же адрес, выданный ключ в secret, ID сообщества и строка confirmation из настроек ВК. Укажите конкретные числовые ID чатов, при необходимости отправителей. На локальном127.0.0.1 внешние вебхуки недоступны; домен/сервер пользователь предоставит позднее. Старую историю бот не читает, используйте экспорт/загрузку.

Получение обычных сообщений не подтверждает требования. Редактирование Telegram сообщения сохраняет новую редакцию того же документа; одинаковые сообщения разных ID не склеиваются. Получение вложений ограничено TLS, известными доменами, размером и отсутствием redirect. ВК в этой версии принимает документы doc и изображения photo; другие типы требуют ручной загрузки. Не загруженное вложение явно помечается.

Для команд пользователь входит в веб-интерфейс, выбирает подключение и вводит свой числовой ID отправителя. Команда /link одноразовая, действует10минут и только для указанного отправителя. Затем /ask ищет локальные источники; /list показывает ID карточек; /change и /new подготавливают изменения через GigaChat. В облако уходит только запрос и выбранная карточка. /confirm и /reject связаны с пользователем, отправителем, предложением, версией и сроком, повторное использование запрещено. Все принятия сохраняются в общей истории.

Ответы включаются явно. Все участники разрешенного чата смогут прочитать отправленные в него ответы по проекту, включая основания. Входящие события проверяются секретом/сообществом/чатом,120запросов в минуту на подключение. Отзыв прав владельца или выключение запрещает дальнейший прием; после AI повторно проверяется конфигурация. При ошибке отправки сохраненный ответ доставляется повторно с последней успешной части; сама команда не запускается повторно. Telegram не предоставляет идемпотентность sendMessage, поэтому при потере HTTP ответа уже доставленная часть может повториться, но принятие решения защищено nonce/CAS.

Реальные токены, чаты и HTTPS сервер пока не заданы, проверены только искусственные события и подмененные вызовы отправки. Сообщения реальным людям не отправлялись.

Протоколы: [Telegram Bot API](https://core.telegram.org/bots/api), [VK callback schema](https://github.com/VKCOM/vk-api-schema/blob/master/callback/objects.json).
