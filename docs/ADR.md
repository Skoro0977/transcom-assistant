# Архитектурные решения

## ADR 001 Компактный локальный запуск

Подтверждено пользователем: сейчас требуется локальная система, сервер будет позже, минимум кода и отсутствие микросервисов. Docker и PostgreSQL не найдены в готовой среде. Поэтому текущий локальный профиль: одно приложение FastAPI, React/Ant Design, один процесс фоновой обработки, SQLite/WAL на D через SQLAlchemy. На этом объеме это сокращает обязательную инфраструктуру. Проектные данные, документы и версии имеют обычные связи и ограничения БД.

PostgreSQL остается предусмотренным серверным профилем через DATABASE_URL. Перед переходом нужны проверка миграции, совместимости и конкурентной нагрузки. pgvector в локальном профиле не заявляется: эмбеддинги сохраняются с моделью и размерностью, точное сходство считается при поиске в пределах доступного проекта. Отдельный векторный сервис не нужен. Обычный поиск доступен независимо от модели.

## ADR 002 Оригиналы и происхождение

Архив заказчика хранится в data/source_archive вне Git. Приложение хранит управляемые оригиналы/редакции отдельно. Не выполняет макросы и встроенные команды. Скрытие из работы сохраняет исходник. Окончательное удаление из архива требует отдельного короткоживущего подтверждения, привязанного к пользователю и документу; история удаления остается без удаленного содержимого. Внешние резервные копии могут содержать старые данные, это предупреждение должно быть видно при удалении.

## ADR 003 Совместная работа

Один закрытый GitHub пользователя Skoro0977, одна интеграционная main, индивидуальные короткие ветки с последующим объединением в main. Это позволяет работать порознь и получать общий результат. Не менять одну общую папку одновременно. Аккаунт коллеги и внешний сервер пока отсутствуют; инструкции и конфигурация готовятся без выдуманных реквизитов.

## ADR 004 Подтверждение

AI предлагает, пользователь принимает. Изменение через чат использует тот же механизм. Набор обычных предложений можно подтвердить вместе, противоречия только по одному. Новая редакция сохраняет предыдущую и автора решения. Все рабочие участники пилота равноправны, роли и права хранятся для дальнейшей настройки.
